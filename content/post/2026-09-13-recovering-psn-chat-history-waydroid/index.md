古い友人とのPlayStation Network(PSN)上でのチャットを、消えてしまう前に手元に残しておきたくなった。使っているのはPCの中の[[Waydroid]]([[Android]]をLinux上で動かす仕組み)で動くPS App。まずはローカルのキャッシュファイルを直接読みに行こうとしたのだが、そこから思いのほか長い調査になった。

---

## ローカルのキャッシュは暗号化されていた

Waydroidのアプリごとのデータは`~/.local/share/waydroid/data/data/<パッケージ名>/`以下にAndroidの`/data`パーティションと同じ構造で保存されている。PS Appのフォルダを覗くと、`databases/`の中にそれらしいファイルが並んでいた。

`file`コマンドで確認すると「OpenPGP Public Key」という判定が出て面食らったが、実際には単に先頭バイトが平文のSQLiteの磁気文字列(`SQLite format 3`)ではなかっただけだった。`xxd`で生のバイト列を見ると、最初から意味のないランダムな値が並んでいる。つまり中身は暗号化されていて、復号する鍵はアプリ側が握っている。ここは早々に諦めた。

## アプリの画面を手で遡るのは、そもそも選択肢に入らなかった

PSNのメッセージはサーバー側に保存されていて、PS4・PS5・スマホのPS Appのどれからでも同じ会話を見られる。だからPS Appを開いて手で遡れば、6年分だろうと全部読めることは最初から分かっていた。

問題はそこじゃない。何年分もの会話を、スクロールしながらスクリーンショットで残していくのがあまりに面倒だった、というだけの話だ。だから、ローカルの暗号化ファイルを諦めた後の次の一手は「手で遡る」ではなく、**サーバーから直接、プログラムでメッセージを取得する**方法を探すことだった。

## PSNは1対1のDMも「Group」として扱っている

PSNには非公式ながら実用に足るPythonラッパー(`psnawp`)がある。ソースを読むと、興味深いことが分かった。

> The Group class manages PSN group endpoints related to messages (**Group and Direct Messages**).

PSN内部では、複数人のグループチャットも1対1のダイレクトメッセージも、どちらも同じ「Group」という概念で扱われている。つまり友人との会話を取得するには、「その人とのGroup」を見つければよく、専用のDM用APIを探す必要はなかった。

## ページネーションのパラメータ名を、独立した別実装から確定させる

`get_conversation()`というメソッドでメッセージを取得できるが、レスポンスには`previous`・`next`というカーソルらしきフィールドと`reachedEndOfPage`という終端フラグが含まれていた。ページネーションができる構造だとは分かったが、**次のページを取るときに渡すクエリパラメータの正式な名前がドキュメントに載っていない。**

最初は`next`という名前を推測で使ったが、動かなかった。ここで、同じPSNの非公式APIを別言語(PHP)で実装している、完全に独立した別プロジェクト(`Tustin/psn-php`)のソースコードを確認した。該当箇所にはこう書かれていた。

```php
if ($cursor != null) {
    $params['before'] = $cursor;
}
...
$this->update($this->totalCount, $results->messages, $results->previous);
```

正しいパラメータ名は`next`ではなく**`before`**で、渡す値はレスポンスの**`previous`**フィールドだった。ドキュメントに載っていない挙動でも、独立した複数の実装を突き合わせれば、推測に頼らず答えを確定できる。

## 実行環境まわりの小さなつまずき

- Arch Linuxでは`pip install --user`が`externally-managed-environment`エラーで弾かれる(PEP 668)。素直に`python -m venv`で仮想環境を作ってそこにインストールする。
- 認証には`NPSSO`という64文字のトークンを使うが、ライブラリのドキュメントには「これはパスワードと同等に扱うべき」と明記されている。人に見せない・チャットに貼らない前提で、ローカルの環境変数として渡す運用にした。

**もう一つ、正直に書いておく。** PSNには公式に公開されたAPIは無く、`psnawp`のようなライブラリはPS Appの内部通信をリバースエンジニアリングしたものだ。**これはPSNの利用規約が禁じる「許可されていない自動化ツールの使用」に該当し、規約違反になる。** 読み取り専用だから軽い、書き込みより安全、という話ではない。規約違反であること自体は読み書き問わず同じで、それを「相対的にリスクが低い」という言い方でぼかすべきではなかった。

## 結果と、届かなかったケース

こうして書いたスクリプトを実行すると、6年近く前、会話グループが作られた時点まで遡って、1万件を超えるメッセージを数分で取得できた。手で遡っていたら、この量は現実的な時間では終わらなかったはずだ。

一方で、もう何年も連絡を取っていない別の知人に同じ方法を試したところ、`Request is rejected due to all targets' settings`というエラーで弾かれた。これは相手の側のプライバシー設定(あるいはブロック)によるもので、こちらの実装や理屈の間違いではない。API がどれだけ正しく動いても、相手側の設定という現実の壁は越えられない。技術的な調査がどこまでも通用するわけではない、という当たり前の事実を確認する形になった。

## まとめ

* Androidアプリのローカルキャッシュが暗号化されていて読めなくても、サービス自体がサーバー同期型なら、諦める前に「アプリの外(API)から取りに行く」道が残っている
* PSNは1対1のDMもグループチャットの一種として内部的に扱っている
* 非公式APIでドキュメントに載っていない挙動は、独立した複数の実装を読み比べることで、推測ではなく根拠を持って確定できる
* 相手のプライバシー設定やブロックは、こちら側の技術力では超えられない現実の壁として存在する
